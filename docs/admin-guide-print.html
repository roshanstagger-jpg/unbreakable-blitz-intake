Blitz Intake — Admin Guide

How to manage the intake sheet and review the blitzes the Unbreakable team submits through the form. For internal admin and CS staff — no coding required.

Form · unbreakable-blitz-intake.vercel.app Backend · the intake Google Sheet For · admin / CS staff
01

How it works

1

Unbreakable submits

A manager opens the form and either creates a new blitz (typing a blitz name) or picks add reps to an existing one, adds the reps and comp, and submits.

2

It lands in the sheet

Each submission becomes one row in Submissions and one row per rep in Rep detail. New reps and blitzes add themselves to the reference tabs.

3

You manage & review

Keep the reference lists current, and use Submissions and Rep detail to onboard reps and hand clean data to payroll.

02

The tabs

Reference tabs are what the form reads — edit them to change what the form offers. Auto-filled tabs are your record of what came in. Config is behind-the-scenes.

TabKindWhat it's for
RosterReferenceMaster rep list. The form's rep picker and default comp read from here. New reps append here with a blank UNB ID for you to assign.
CompPlansReferenceSequifi's named rate plans (Rate 200, Rate 250…). The form's comp dropdown reads this. Add a row to add a plan.
ISPsReferenceThe ISP chips on the form. Add a row (name + abbreviation) to make a new ISP selectable.
BlitzesReferenceThe list behind "add reps to an existing blitz." New blitzes submitted on the form append here automatically.
SubmissionsAuto-filledOne row per submission, each with a Submission ID. Your master log of everything that came in.
Rep detailAuto-filledOne row per rep per blitz — built for payroll. Comp plan, comp $, and the overrides that apply to each rep.
ConfigConfigStores the uploaded logo. Leave it alone.
03

Managing the lists

  • Editing a reference tab changes the form. Add a rep, a comp plan, or an ISP by adding a row — no developer needed.
  • Changes appear when the form is reloaded, not live in a tab that's already open. Tell submitters to refresh if they don't see a new option.
  • Use the Active column to hide, not delete. On CompPlans, ISPs, and Blitzes, set Active to no to retire an item without losing its history.
  • Dedupe happens on email. When a rep is added twice, the sheet keeps one Roster entry — keep emails accurate.
  • Don't rename header rows or delete the Submissions / Rep detail tabs — the form writes to those exact columns.
04

Reviewing submissions

  • Start in Submissions. Each row is one submission. The Submission ID looks like UNB-20260712-001 (date + that day's sequence). The Full summary column is a plain-English recap.
  • A blitz marked (+reps added) means reps added to an existing blitz, not a brand-new one.
  • Use Rep detail for payroll. One row per rep: comp plan, comp $, new-rep flag, and the manager/divisional overrides resolved onto their row. Filter by Blitz or Submission ID.
  • New reps to onboard show New rep? = yes with a blank UNB ID — that's your onboarding queue.
  • Export anytime: File → Download → Microsoft Excel (.xlsx).
Tip: create a Filter view (not a plain filter) on Rep detail so you can slice by blitz or office without disturbing what teammates see.
05

Common tasks

Onboarding

Onboard a new rep

Find New rep? = yes in Rep detail (or a blank UNB ID in Roster). Create them in Sequifi, then paste their UNB ID back into the Roster row.

Reference

Add a comp plan or ISP

Add a row to CompPlans (plan name + rate) or ISPs (name + abbreviation). It appears in the form on next reload.

Reference

Retire an old blitz

In Blitzes, set that row's Active to no. It stops showing in the "add reps" picker but stays on record.

Branding

Change the logo

Open the form → Upload logo → pick the image. It saves to the sheet and shows for everyone. Use an SVG or a small PNG.

Setup

Connect a new browser

If the form shows Roster offline, click Connect / Change sheet and paste the Web App URL ending in /exec.

Reference

Fix a rep's comp

Edit their Default plan in Roster. That sets the form's pre-fill only — actual comp is chosen per blitz at submit time.

06

Troubleshooting

  • “Roster offline — using cache.” The form couldn't reach the sheet. Re-paste the /exec URL via Connect; if it persists, the Apps Script Web App needs access set to Anyone and a fresh deployment.
  • A new rep / plan / ISP isn't showing. Reload the form — reference tabs load on open, not live.
  • Two people editing at once. Fine. Submissions are written under a lock, so simultaneous submits won't collide.
  • A submission didn't appear. Check the submitter had the form connected (green dot) and hit Submit — an offline form can't write.
07

Train a new admin (15 minutes)

  1. Open the intake sheet together and walk through the tabs using section 02.
  2. Open the form, connect it, and submit one test blitz with two reps (make one a brand-new rep).
  3. Find that submission in Submissions — point out the Submission ID and Full summary.
  4. Open Rep detail and show the two rep rows, the comp columns, and the New rep? = yes flag.
  5. Confirm the new rep landed in Roster with a blank UNB ID; assign one.
  6. Edit a reference row (e.g. add a comp plan), reload the form, and watch it appear.
  7. Export Rep detail to Excel to show the payroll hand-off.
